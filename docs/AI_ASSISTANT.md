# BotBuilder AI Assistant Architecture (`docs/AI_ASSISTANT.md`)

## 1. Executive Summary & Goals

The BotBuilder AI Assistant is a specialized, sidecar-assisted agent designed to help users build Telegram bot scenarios and extend application capabilities with custom plugins.

Unlike generic LLM wrappers, the BotBuilder AI module enforces strict graph validation, automated schema self-correction, dynamic plugin catalog synchronization, and server-side graph auto-layout.

### Key Architectural Principles

* **Schema-Guaranteed Generation:** All scenario mutations (creation or updates) are validated using Pydantic v2 models before reaching the Canvas.
* **Self-Correction Retry Loop:** If an LLM outputs malformed JSON or invalid schema structures, the system catches the exact validation error and feeds it back to the model for an automatic fix (up to 2 retries).
* **Hot-Reloading Plugin Sync:** Custom plugins generated by AI are dynamically re-indexed via `PluginManager.reload_user_plugins()` without requiring application restarts.
* **Compact Context Serialization:** Scenarios are serialized into lightweight topological descriptions (`serialize_scenario_for_llm`) to prevent context window bloat.
* **Zero Direct Renderer-to-LLM Traffic:** The Electron UI renderer communicates only with the local FastAPI sidecar via `apiFetch`.
* **Canvas Adapter:** LLM connection schema (`from_block_id` / `from_port` / `to_block_id` / `to_port`) is converted to runtime canvas shape (`from` / `outputIndex` / `to`) before `loadScenarioData`.

## 3. Data Validation Schemas (Pydantic v2)

Located in `backend/services/ai_scenario_ops.py`.

```python
class BlockConnection(BaseModel):
    id: str
    from_block_id: str
    from_port: str          # e.g. "0", "out", "true"
    to_block_id: str
    to_port: str = "in"

class ScenarioBlock(BaseModel):
    id: str
    type: str
    x: int = 0
    y: int = 0
    data: Dict[str, Any] = {}

class ScenarioDocument(BaseModel):
    blocks: List[ScenarioBlock]
    connections: List[BlockConnection]

class ScenarioPatch(BaseModel):
    add_blocks: List[ScenarioBlock] = []
    update_blocks: List[ScenarioBlock] = []
    remove_block_ids: List[str] = []
    add_connections: List[BlockConnection] = []
    remove_connection_ids: List[str] = []
```

`BlockConnection` also accepts legacy canvas fields (`from`, `to`, `outputIndex`) via `model_validator` and converts with `.to_canvas()`.

## 4. Self-Correction Retry Loop

`AIProvider.call_structured_llm(messages, response_model, max_retries=2)`:

1. Call LLM (`json_mode` preferred).
2. `response_model.model_validate_json(...)`.
3. On `ValidationError`: append assistant raw + user correction prompt with the exact error; retry.
4. Emit validation failures to System Monitor (`LLM` layer).

## 5. Dynamic Plugin Catalog & `ai_capabilities`

Each plugin `ui.json` exposes:

```json
"ai_capabilities": {
  "summary": "...",
  "can": ["..."],
  "cannot": ["..."],
  "when_to_use": "...",
  "data_shape_hint": "...",
  "ports": ["0"]
}
```

### Hot-Reload Pipeline

1. `POST /api/ai/generate-plugin` saves to `%AppData%/botbuilder-desktop/data/plugins/{type}/`.
2. Backend calls `PluginManager.reload_user_plugins()`.
3. Response includes updated `plugin_catalog`.
4. Frontend `reloadPlugins()` refreshes palette; sample block may be inserted on canvas.
5. `POST /api/ai/scenario-op` rebuilds catalog before the system prompt.

## 6. Backend API (`/api/ai/*`)

| Endpoint | Role |
|----------|------|
| `GET /status` | enabled, model, catalog |
| `POST /chat` | Quiet intent JSON (`clarify` / `need_plugin` / `ready_replace` / `ready_patch` / `answer`) |
| `POST /generate-plugin` | Create plugin + hot-reload + return catalog |
| `POST /scenario-op` | `replace` \| `patch` + validate + layout |
| `POST /generate-scenario` | Legacy alias → replace |

---

## 7. Auto-Layout Grid Engine

`layout_blocks_grid` in `ai_scenario_ops.py`:

1. Entry roots: `start`, then `command`, else first block.
2. BFS depth levels.
3. Spacing: **ΔX = 320px**, **ΔY = 160px** (base 100,100).
4. Orphans placed to the right.

---

## 8. Frontend (`AiPanel.js`)

* History: `window.__bbAiChatHistory` — full array sent to `/scenario-op` and `/chat`.
* Canvas snapshot: `window.editor.getScenarioData()` / `getScenarioData()`.
* Cards: plugin (preview / create / skip), scenario (apply replace|patch / cancel).
* After plugin create: reload palette → optional `createBlock(type)` → notify chat context.

---

## 9. Logging & Security

* Layer: `LLM`
* Line: `OK|FAIL · purpose · model · duration_ms`
* Detail (expandable): endpoint, system/user/response trim, validation traces
* **Never logged:** API keys, Bearer tokens (`sanitize_secrets` in `ai_provider.py`)
